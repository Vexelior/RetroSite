Then vs. Now
How web design changed between 1997 and 2026

A lot of 90s design choices look silly now, but almost all of them were smart answers to real limits: slow modems, small screens, 256 colors, and browsers that didn't agree with each other. Here's what web designers dealt with then, and what they do now.

  THEN (around 1997) NOW (2026)
Getting online A 28.8k or 56k dial-up modem that tied up the phone line. A 100 KB page could take half a minute, so pages had to be tiny. Broadband, Wi-Fi, and phone networks. Typical pages now weigh several megabytes, but people still leave if a page feels slow, so speed still matters.
Screens Bulky CRT monitors at 640x480 or 800x600. Designers built one fixed-width page and put up a "best viewed at 800x600" button. Phones, tablets, laptops, and huge monitors, with high-density "retina" displays. Responsive design lets one page fit every screen.
Layout Nested <TABLE>s, spacer GIFs, <CENTER>, and frames. CSS Flexbox and Grid, plus container queries. Tables are only used for real tables of data.
Styling <FONT FACE COLOR SIZE> on every paragraph, and BGCOLOR on every cell. Changing the look of a site meant editing every page by hand. Style sheets kept apart from the content, with variables, dark mode, and design systems shared across whole companies.
Fonts Whatever was installed on the visitor's computer: Times New Roman, Arial, Courier, Verdana, and Comic Sans. Anything fancier had to be an image. Web fonts load right along with the page, so designers can use almost any typeface, including variable fonts that change weight and width.
Color The 216 web-safe colors, because many visitors only had 256-color displays. Millions of colors, wide-gamut color spaces, and contrast checks so text is easy to read for everyone.
Motion Animated GIFs, <BLINK>, <MARQUEE>, Java applets, and later, Flash. CSS transitions and animations, video, and SVG, often turned down for visitors who ask for less motion in their settings.
Interactivity Forms sent to a Perl CGI script (or just mailto:), then a whole new page loaded. JavaScript was mostly for rollovers and pop-ups. Full applications in the browser, updating the page without reloading, built with JavaScript frameworks and APIs.
Browsers Netscape vs. Internet Explorer, each with its own tags. Upgrading meant downloading a new version, sometimes from a CD in a magazine. "Evergreen" browsers that update themselves and mostly follow the same web standards.
Building it Notepad or SimpleText, Microsoft FrontPage, Netscape Composer, or Dreamweaver. Upload with FTP. Learn by choosing "View Source" on other people's pages. Code editors, build tools, version control, website builders, and AI helpers. (View Source still works, though!)
Hosting Free space from GeoCities, Angelfire, or Tripod, or the few megabytes your ISP gave you. Long URLs like geocities.com/Area51/Nebula/1234/. Cloud hosting and free static hosts that deploy straight from a code repository, with your own domain name.
Community Guestbooks, webrings, link pages, and award badges. You found new sites by clicking from one homepage to another. Social media, comments, and search engines. Most people's "homepage" is a profile on someone else's site.
Who's visiting? A hit counter at the bottom of the page. Analytics dashboards (and cookie consent banners).
Accessibility Rarely thought about. Text inside images, missing ALT text, and image-map menus made many pages hard to use with a screen reader. Accessibility guidelines (WCAG), semantic HTML, and in many places, laws requiring that sites work for everyone.

What we lost: 90s homepages were weird, personal, and handmade. Anyone could look at the source of a page they liked and learn how it was done. That spirit hasn't died, though: people are still building personal sites, webrings, and 88x31 buttons on the "small web" today.
